# PWA: инженерные правила (проверены на BAR)

Это механика, а не дизайн: как устроено, чтобы приложение вело себя как нативное. Как оно выглядит — решает
скилл `design-system` проекта.

## 1. Состояние и навигация

- **Всё, чем можно поделиться или к чему вернуться, — в URL**: фильтры и поиск — в query (`?q=…&tag=…`), открытая
  шторка / модальный слой — в хэше (`#filters`, `#item-<id>`). Тогда работают «Назад», прямые ссылки и обновление страницы.
- **Системное «Назад» закрывает верхний слой**, а не уходит со страницы: открытие шторки — `navigate({ hash }, { state: { sheet: true } })`,
  закрытие — `navigate(-1)`, если шторку открыли мы, иначе `replace` без хэша. Прямой заход по ссылке с хэшем —
  подложить запись без хэша, чтобы «Назад» закрыл слой, а не выкинул из приложения.
- Ввод текста в поиске — `replace`, а не новая запись истории на каждую букву.
- «Назад» на странице без истории (открыли по ссылке) — переход на родителя, а не `navigate(-1)` в никуда.
- Форма с несохранёнными правками — `useBlocker` (только на смену пути, не на хэш шторок) + вопрос перед уходом.

## 2. Базовый путь и хостинг

- Одна кодовая база, два адреса: тестовый стенд в подпапке (`/<repo>/` на GitHub Pages) и продакшен от корня.
  Базовый путь — только из `import.meta.env.BASE_URL` (роутер — `basename`, манифест — `start_url`/`scope`/`id`,
  иконки — относительные пути). Абсолютные `/…` ссылки на ресурсы в коде не писать.
- GitHub Pages не знает SPA-роутов: копия `index.html` → `404.html` (`scripts/spa-fallback.mjs`).
- Служебные страницы (каталог компонентов, превью экранов) — только на тестовом стенде: маршруты за флагом
  сборки (`VITE_INTERNAL=0` в продакшене), чтобы код вообще не попал в бандл.

## 3. Офлайн и обновления

- Service worker (`vite-plugin-pwa`, `autoUpdate`): прекэш сборки, офлайн-навигация на `index.html`.
  Крупное и редкое (заставки iPhone, og-картинка) — в `globIgnores`, браузер берёт их сам.
- Кэш на хостинге: хэшированные `/assets/*` — `immutable` на год; `sw.js`, `registerSW.js`, манифест, `index.html` —
  `max-age=0, must-revalidate`, иначе телефоны застрянут на старой версии.
- Шрифты и картинки — локальные: без CDN и внешних запросов приложение работает без сети.

## 4. Установка и standalone

- Standalone-режим: `matchMedia('(display-mode: standalone)')` или `navigator.standalone` (iOS).
- **Android/Chrome:** `beforeinstallprompt` перехватить рано (до рендера), показать свою кнопку «Установить»,
  `prompt()` по тапу; нет события — инструкция через меню браузера.
- **iPhone:** программной установки нет — инструкция «Поделиться → На экран Домой». Нужны `apple-touch-icon` 180,
  `apple-mobile-web-app-*` и `apple-touch-startup-image` под размеры экранов, иначе при запуске белая вспышка.
- **Браузеры мессенджеров** (Telegram, Instagram, VK, WebView) установить не дают — распознать по UA и попросить
  открыть в Safari / Chrome.
- Данные в `localStorage` у установленного PWA на iPhone **отдельные** от Safari: то, что человек отметил в браузере,
  в приложение не переедет — по ссылке лучше сразу вести на установку.
- В standalone на iPhone **нет системного свайпа «назад»** — нужен свой жест от края или заметная кнопка «Назад».
- `overscroll-behavior: none` на корне — без «резины» и pull-to-refresh.

## 5. Данные на устройстве

- Ключи `localStorage` с версией (`<app>-<что>-v1`); меняется форма — мигрировать в `load()` или менять ключ.
- Хранилище может быть недоступно (приватный режим) — оборачивать в `try/catch`, показывать, что данные не сохранятся.
- Общий стор — `useSyncExternalStore` над `localStorage`, синхронизация вкладок через событие `storage`.
- Справочники и контент — статический JSON с валидатором (`scripts/validate-*.mjs`) в CI.

## 6. Первый запуск

- Онбординг / подсказки первого запуска — флаг в `localStorage`; не показывать тем, у кого уже есть данные
  (тестировщики), и не перебивать прямую ссылку на конкретный экран.
- Отдельный адрес для просмотра онбординга, который не меняет данные, — для ревью на тестовом стенде.
- Скрипты скриншотов ставят флаг «пройдено», чтобы онбординг не перекрывал снимки (флаг `--intro` — снять его).

## 7. Переходы и отклик

- Переходы страниц — View Transitions API (react-router: `viewTransition`); нет API — мгновенная смена, всё работает.
  Вид перехода (вглубь / назад / вкладка) — атрибутом на `<html>`, направление «назад» — из `popstate`.
- Платформа (iOS / Android) — атрибутом на `<html>` по UA, с ручным переключателем на тестовом стенде:
  движение можно делать разным под платформы, токены — в CSS.
- Закрывающиеся слои (шторки, тосты) живут ещё длительность анимации выхода, показывая прежнее содержимое.
- `prefers-reduced-motion` — только fade.
- Тактильный отклик: `navigator.vibrate` есть только на Android; на iPhone — визуальное pressed-состояние всегда.

## 8. Производительность

- В длинных списках — без `filter: blur` / `backdrop-filter` на каждом элементе: тени и свечения градиентами.
- Проверять прокрутку с замедлением процессора ×4 (CDP `Emulation.setCPUThrottlingRate`), цель — кадр ≤ 17 мс.
- Тяжёлые служебные страницы — отдельным чанком (`lazy`).

## 9. Проверки

- Перед пушем: `npm test`, `npm run build` (строже, чем `tsc --noEmit`: ловит неиспользуемые импорты).
- Визуально — скриншоты 390×844 через `Read`; анимации — кадрами с замедлением (CDP `Animation.setPlaybackRate`);
  сценарии — Playwright-скриптом с проверкой ошибок консоли и битых ответов.
- Продакшен-сборку проверять локально так, как её соберёт хостинг (те же переменные окружения): установка,
  прямые ссылки, офлайн, манифест.
- Массовая проверка однотипных экранов скриптом (все карточки / все страницы): переполнение, обрезка, контраст,
  `NaN` в SVG.
