# Дизайн-система {{APP}}

Статус: **v0** — пустой каркас. Визуальный язык проекта свой: разделы 1–6 заполняются на первых итерациях
(`/ref` по референсам → правила сюда → компоненты в каталог `/design-system`).

Как вести этот файл:
- Каждое правило — проверяемое значение («радиус карточки 24», «поле 56»), а не вкус («мягко», «крупно»).
- Правило из референса помечается источником `[Mobbin: App — экран]`, решение владельца — «(решение владельца)».
- Противоречие нового правила старому — не молча перезаписывать, а показать конфликт и спросить.
- Отменённое — вычёркивать с пометкой, почему (чтобы не вернуть по ошибке).

## 1. Принципы

_Заполнить: 3–5 принципов продукта и визуального языка._

## 2. Сетка и отступы

_Заполнить: базовый вьюпорт, шаг сетки, края экрана, ритм секций._

## 3. Тач-зоны и safe-area

- Минимальная тач-зона **44×44** (Apple HIG) / 48×48 (Material) — даже если иконка меньше, расширять паддингом.
- `viewport-fit=cover`; отступы от вырезов и жестовой полосы — через `env(safe-area-inset-*)`.

## 4. Цвет

_Заполнить: таблица токенов (фон, поверхности, текст 1–3, акцент, текст на акценте, граница, статусы), темы._

## 5. Типографика

_Заполнить: шкала стилей, шрифты (локальные — PWA работает офлайн)._

## 6. Радиусы, тени, движение

_Заполнить: радиусы, тени, токены длительностей и кривых._ Компоненты используют только токены — значения в одном месте.

## 7. Компоненты

_Заполняется по мере появления: компонент → варианты → состояния → где используется._

## 8. Паттерны из референсов

_Пополняется командой `/ref`: «правило → значение → [Mobbin: App — экран] → файл в refs/»._

## 9. Чек-лист визуальной проверки (для `/look` и `ui-inspector`)

- [ ] Ничего не выходит за ширину экрана, нет горизонтального скролла.
- [ ] Все интерактивные элементы — не меньше минимальной тач-зоны.
- [ ] Текст не обрезан неожиданно (обрезка только намеренная, с `…`).
- [ ] Контраст текста ≥ 4.5 (WCAG AA), вторичный текст читается.
- [ ] Отступы по шкале, края экрана одинаковые.
- [ ] Учтены safe-area сверху и снизу.
- [ ] Один главный акцент на экран.
- [ ] Состояния loading / empty / error не «прыгают» по геометрии относительно content.
- [ ] Нет ошибок в консоли; анимации и переходы проверены кадрами.
