# {{APP}} — {{TAGLINE}} (PWA)

Мобильное PWA-приложение. Процесс разработки внутри Claude Code: план → дизайн-система → экран →
визуальная проверка → тестовый стенд → продакшен.

## Стек

- Vite + React + TypeScript (strict) + Tailwind CSS + Lucide Icons + `vite-plugin-pwa`.
- Mobile-First. Базовый вьюпорт **390×844** (iPhone 14/15). Эстетика нативного iOS/Android: крупные
  заголовки, мягкие скругления, нижние шторки, тактильный отклик на нажатие.
- Backend нет / {{BACKEND}}.

## Команды

- `npm run dev` — dev-сервер, http://127.0.0.1:{{PORT}} (порт фиксированный, `--strictPort`).
- `npm run build` — `tsc` + сборка в `dist/` от корня `/` (локально, Vercel).
- `npm run build:gh-pages` — сборка с `BASE_PATH=/{{REPO}}/` + `dist/404.html` для прямых ссылок.
- `node scripts/serve-gh-pages.mjs` — локальная эмуляция GitHub Pages на http://127.0.0.1:4174/{{REPO}}/.
- `npx tsc --noEmit` — проверка типов (её же запускает хук после каждой правки `.ts/.tsx`).
- `npm test` — unit-тесты (vitest, `src/**/*.test.ts`).
- `node scripts/screenshot.mjs <роут> [имя] [--full] [--intro] [--click <локатор>]` — скриншот 390×844 @2x
  в `.screenshots/`; `--click` повторяемый (Playwright-локатор); онбординг первого запуска пропускается, `--intro` — снять его.
- `python3 scripts/split-shot.py <png>` — нарезать длинный скриншот на экраны по 844.
- `python3 scripts/montage.py out.png a.png b.png …` — склеить скриншоты в ряд.
- `node scripts/make-icons.mjs` — иконки PWA из `public/favicon.svg`.
- `node scripts/make-splash.mjs` — заставки запуска iPhone (`public/splash/`), печатает `<link>` для `index.html`.

## Хостинг и поток релиза

- **Две площадки:** на GitHub Pages проверяем фичи и идеи, на Vercel — только готовый функционал.
  1. Работа идёт в ветках `claude/**` → каждый пуш публикует **тестовый стенд** https://{{OWNER}}.github.io/{{REPO}}/
     (`.github/workflows/deploy-gh-pages.yml`; полный доступ в браузере, витрина `/design-system`).
  2. Когда владелец принял фичу — она уходит в `main` → **Vercel** публикует продакшен. Превью-деплои веток
     `claude/**` на Vercel выключены (`vercel.json` → `git`). Пуш в `main` — только по явному «принимаю».
- **Vercel — продакшен:** от корня `/`, `vercel.json` (rewrites → `index.html`, кэш: `/assets/*` — навсегда,
  `sw.js`/манифест/`index.html` — без кэша). Сборка `VITE_INSTALL_PAGE=1 VITE_INTERNAL=0`: в браузере — только страница
  установки, приложение — после установки (с экрана «Домой»); служебных страниц (`/design-system` и т. п.) нет.
  Node ≥ 22.12 (`engines`).
- Базовый путь — только через `import.meta.env.BASE_URL` (роутер — `basename`, манифест — `start_url`/`scope`,
  иконки — относительные пути). Абсолютные `/…` ссылки на ресурсы в коде не писать: на Pages они уйдут мимо
  `/{{REPO}}/`. Ссылки роутера (`<Link to="/">`) — можно.

## Процесс (обязателен)

1. `/idea <фича>` — только продуктовое мышление, код не пишем. Результат — `plan.md`. Ждём «го».
2. `/code` — реализовать утверждённый `plan.md`: **сначала** компоненты в каталоге `/design-system`, **потом** экран.
3. `/look <роут>` — скриншот, разбор глазами, исправление огрехов.
4. `/ref <ссылка|описание>` — новый референс из Mobbin → правила в скилл `design-system`.
5. Готово → пуш в `claude/**` → владелец смотрит тестовый стенд → «принимаю» → `main` → Vercel.

Субагенты: `ui-inspector` (визуальная критика по скриншотам){{AGENTS}}.

## Правила

- **`/design-system` — источник истины.** Любой UI-элемент экрана сначала появляется в каталоге
  `/design-system` со всеми состояниями (default, pressed, disabled, empty, loading), и только потом
  используется в экране. Новые компоненты в обход каталога не заводить.
- **Только токены.** Цвета, радиусы, отступы, тени, шрифты, длительности анимаций — из токенов
  (CSS-переменные / Tailwind), описанных в скилле `design-system`. Никаких «магических» `#hex` и `px` в компонентах.
- **Тач-зоны ≥ 44×44 px**, safe-area через `env(safe-area-inset-*)`.
- **Визуальная проверка обязательна.** После вёрстки любого компонента или экрана: dev-сервер →
  `node scripts/screenshot.mjs <роут>` → открыть `.png` через `Read` → проверить (съехавшие блоки, мелкие кнопки,
  контраст, обрезанный текст, safe-area) → исправить → повторить. Показывать результат только после чистого скриншота.
  Анимации — кадрами с замедлением (CDP `Animation.setPlaybackRate`), сценарии — Playwright-скриптом с проверкой
  ошибок консоли.
- **Типы не ломаем.** Хук `PostToolUse` гоняет `tsc`; при ошибке — чинить сразу. Перед пушем — `npm run build`
  (он строже `tsc --noEmit`: ловит неиспользуемые импорты) и `npm test`.
- **Скриншоты: черновые и финальные.** Черновые — в `.screenshots/` (не коммитим). Финальные каждого этапа —
  в `docs/previews/` с именем `<этап>-<экран>[-<состояние>].png`, коммитим и обновляем `docs/previews/README.md`
  (что на скриншоте, дата, этап). Владелец смотрит их на GitHub.
- Референсы: `refs/` (скриншоты из Mobbin, файлы владельца). Mobbin — через MCP (`search_screens` / `search_flows`).
- Каждый коммит и пуш — в конце хода; рабочее дерево чистое.
- Интерфейс — на русском. Шрифты — только локальные (без CDN, работают офлайн).
