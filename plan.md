# План: MVP — Итерация 1 (каталог + карточка рецепта)
Статус: черновик — ждёт утверждения

Подход — vertical slice: рабочий продукт из двух экранов; в `/design-system`
попадает **только** то, что реально используется в этих экранах.

## Зачем

Человек дома или в гостях хочет быстро выбрать коктейль из того алкоголя,
что под рукой, и приготовить его без ошибок в пропорциях — на 1, 2 или 4
гостей. MVP проверяет ядро ценности: «выбрал базу → увидел варианты →
открыл рецепт → смешал по чек-листу».

## Сценарий

1. Открываю приложение (иконка PWA на домашнем экране) → сразу вижу сетку
   атмосферных карточек.
2. Тапаю чипс «Ром» → сетка мгновенно сужается, счётчик «2 коктейля».
3. Тапаю карточку «Дайкири» → детальная: обложка, метод/бокал/лёд/крепость.
4. Переключаю порции на «2×» → все мл пересчитались на лету.
5. Отмечаю ингредиенты по мере наливания → строки зачёркиваются; читаю
   шаги; «Назад» → возвращаюсь в каталог с тем же фильтром и позицией скролла.

## Навигация и жесты

- Тап по карточке → `/cocktail/:slug` (вся карточка — ссылка `<a>`, работает
  долгий тап/открыть в новой вкладке).
- «Назад»: кнопка на обложке, системный свайп назад в Safari и кнопка
  браузера — всё через history, фильтр и скролл каталога сохраняются.
- Чипсы: тап выбирает (одиночный выбор), повторный тап по выбранному → «Все».
- Тач-зоны: чипс 36 визуально / 44 тап; IconButton 44; GlassIconButton 36/44;
  строка чек-листа ≥ 48; сегмент ≥ 44 по высоте тап-зоны.
- Анимации: pressed 100/200ms; пересчёт мл — без анимации цифр в MVP
  (tabular-nums, чтобы не прыгала ширина); `prefers-reduced-motion` уважаем.

## Данные

Наполнение — субагент **`bartender`** по скиллу `cocktail-data`.
12 коктейлей, по 2 на базу:

| База (`base`) | Коктейли | Бокал |
|---|---|---|
| Джин `gin` | Драй Мартини, Том Коллинз | martini, collins |
| Ром `rum` | Дайкири, Мохито | coupe, highball |
| Виски `whiskey` | Олд Фэшн, Виски Сауэр | rocks, rocks |
| Текила `tequila` | Маргарита, Палома | coupe, highball |
| Водка `vodka` | Московский мул, Космополитен | highball, martini |
| Аперитивы `aperitif` | Негрони, Апероль Шприц | rocks, wine |

**Изменения схемы** (обновить скилл `cocktail-data` и `src/types/cocktail.ts`):
- `base: "gin" | "rum" | "whiskey" | "tequila" | "vodka" | "aperitif"` —
  главная база для чипсов (Негрони → `aperitif`, хотя в нём джин).
- `cover: { from: string; to: string }` — два hex цвета градиента обложки,
  атмосферные и близкие к реальному цвету напитка (Негрони — рубиново-
  красный → тёмно-бордовый). Это **данные**, а не UI-токены — исключение
  из правила «только токены», фиксируем в скилле. Требование: белый текст
  названия на скриме читается (проверка на скриншоте).
- `glass` в MVP — подмножество из 6 силуэтов: `rocks`, `coupe`, `highball`,
  `collins`, `martini`, `wine`. Остальные значения словаря маппятся на
  ближайший (`double-rocks`→`rocks`, `nick-and-nora`→`coupe`,
  `copper-mug`→`highball`…).
- Пересчёт порций: `amountMl × n` и `amount × n`; `top` («долить») не
  умножается.
- Валидация `bartender`: 2 коктейля на каждую базу, все `glass` из 6 силуэтов,
  оба цвета `cover` — валидный hex.

## Технические решения

- Vite + React 19 + TS strict, Tailwind v4 (`@tailwindcss/vite`), токены —
  CSS-переменные в `:root` / `[data-theme="light"]`, прокинутые в `@theme`.
- Роутинг — `react-router` (2 роута + `/design-system` + 404).
- `vite-plugin-pwa`: manifest (`name: "BAR — коктейли"`, `display: standalone`,
  `theme_color`/`background_color` = `--bg` тёмной темы, иконки 192/512 +
  maskable), precache всего бандла; `viewport-fit=cover`.
- Шрифт — системный стек, без внешних запросов.
- Unit-тесты (vitest): пересчёт порций, склонение «коктейль/коктейля/коктейлей»,
  фильтр по базе.

## Порядок работ для `/code`

1. Каркас: Vite + TS + Tailwind + router + PWA + токены + переключатель темы;
   хук `tsc` начинает работать.
2. `bartender` → `src/data/cocktails.json` + обновление скилла `cocktail-data`.
3. Витрина `/design-system`: токены, типографика, компоненты из таблицы.
   Скриншоты обеих тем → `Read` → правки.
4. Экран каталога → скриншоты → правки.
5. Экран рецепта (1× и 2×, с отмеченными ингредиентами, 404) → скриншоты → правки.
6. `ui-inspector` — независимый разбор, закрыть P0/P1.
7. `npm run build` + `npm test`; финальные превью в `docs/previews/`.

## Критерии готовности (проверяемые на скриншоте)

- [ ] `/design-system` в тёмной и светлой теме: все компоненты из таблицы со
      всеми состояниями; ничего не шире 390px.
- [ ] Каталог 390×844: large title, ряд чипсов уходит за край, счётчик,
      ровно 2 колонки 167px, 2 полных ряда видны без скролла.
- [ ] Каталог с фильтром «Ром»: выбран чипс, «2 коктейля», 2 карточки.
- [ ] У всех 12 карточек свой градиент и правильный силуэт бокала; названия
      в 2 строки читаются на скриме; стеклянная плашка видна.
- [ ] Рецепт 1×: обложка ≈ 55% высоты, «Назад» не под статус-баром,
      StatGrid в 4 ровные колонки без переносов, начало «Ингредиентов» в
      первом экране.
- [ ] Рецепт 2×: все мл удвоены, «долить» без числа, ширина колонки объёмов
      не прыгает.
- [ ] Рецепт с 2 отмеченными ингредиентами: зачёркнуты, `text-3`, чекбоксы
      залиты акцентом.
- [ ] 404 по неизвестному slug: сообщение + кнопка «В каталог».
- [ ] Обе темы на обоих экранах: контраст текста достаточный.
- [ ] Тач-зоны ≥ 44 у всех интерактивных элементов (проверка размеров в DOM).
- [ ] `npm run build`, `npm test` зелёные; в консоли браузера нет ошибок.
- [ ] Финальные превью: `docs/previews/step2-*` (design-system ×2 темы,
      каталог ×2 темы + фильтр, рецепт 1×/2×/checked ×2 темы, 404).
