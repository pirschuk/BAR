# План: Движение и PWA на iPhone и Android
Статус: **сделано** (2026-10-26)

## Зачем

Сейчас интерфейс «щёлкает»: страницы подменяются мгновенно, шторка появляется снизу, а закрывается в ноль кадров,
тост исчезает без следа, вкладки переключаются без перехода. Нативные приложения так не выглядят — это главный
источник ощущения «дёшево». Вторая половина: в установленном PWA на iPhone **нет системного свайпа назад и кнопки
«Назад» браузера** — сейчас человек может уйти назад только кнопкой ‹ в навбаре. На Android назад работает
системным жестом, но без анимации.

Цель — движение, которое ощущается родным на каждой платформе: на iPhone — как UIKit, на Android — как Material 3,
одним кодом, без тяжёлых библиотек.

## Сценарий

1. ~~Каталог → тап по карточке: обложка вырастает в обложку рецепта~~ — отменено (18c): карточка открывается обычным переходом вглубь.
2. Рецепт → свайп от левого края (iPhone): страница едет за пальцем, под ней виден приглушённый каталог;
   отпустил дальше трети или быстро — уходит, иначе возвращается. На Android — системный жест «назад» с
   предиктивной анимацией (страница уменьшается и уезжает).
3. «Фильтры» → шторка выезжает с пружиной, скрим проявляется; свайп вниз / тап по скриму / «Назад» —
   шторка **уезжает вниз**, скрим гаснет.
4. Применил фильтр → карточки плавно перестраиваются (исчезнувшие гаснут, оставшиеся переезжают).
5. Переключил вкладку «Каталог ↔ Мой бар» → короткий переход без «прыжка»; ♡, тост, «Сохранить» — с откликом.

## Язык движения (токены)

| Токен | iPhone (UIKit) | Android (Material 3) |
|---|---|---|
| Переход «вглубь» (push) | новая страница справа 100% → 0, старая уезжает на 30% влево и темнеет; 350 мс, `--ease-ios` cubic-bezier(.32,.72,0,1) | shared axis X: новая +30 px и fade-in, старая −30 px и fade-out; 300 мс, `--ease-emph` cubic-bezier(.05,.7,.1,1) |
| Назад (pop) | обратное; интерактивно — за пальцем | предиктивный «назад»: страница сжимается до 90% и уезжает вправо |
| Вкладки | без сдвига, crossfade 150 мс | fade-through 200 мс (старое гаснет, новое проявляется с 92% масштаба) |
| Шторки | вход 400 мс пружина, выход 250 мс ease-in вниз; скрим 0 → 40% | вход 350 мс emphasized, выход 200 мс |
| Общий элемент карточка → обложка | 450 мс, обе платформы | так же |
| Тост | вход снизу + fade 200 мс, выход вниз 160 мс | так же |
| Перестройка сетки | 250 мс | так же |
| reduced-motion | только fade 150 мс, без сдвигов и масштаба | так же |

Длительности и кривые — CSS-переменные в `index.css` по `html[data-platform="ios|android"]`, компоненты используют
только токены (как цвета и отступы сейчас).

## Как сделаем (технически)

- **View Transitions API** (Safari 18+, Chrome 111+) — переходы страниц, общий элемент, перестройка сетки.
  react-router 8 включает их флагом `viewTransition` у `<Link>`/`navigate`; направление (push/pop) — классом
  на `<html>`. Нет API → без анимации, всё работает как сейчас.
- **Платформа** — `data-platform` на `<html>` по `userAgentData`/UA (iPhone, iPad → ios; остальное → android-стиль).
- **Свайп назад на iPhone** — свой жест у левого края (20 px) только в установленном PWA (`display-mode: standalone`);
  в Safari-вкладке его делает сам браузер — не дублируем.
- **Шторки и тосты** — состояние «закрывается»: компонент живёт ещё ~250 мс, проигрывает выход, потом размонтируется.
  Свайп шторки вниз учитывает скорость (быстрый смах закрывает даже с короткого хода).
- **Тактильный отклик** — Android: `navigator.vibrate(10)` на ♡, «Сохранить», переключателях; iPhone вибрацию из веба
  не даёт — визуальный отклик (pressed) обязателен везде.

## PWA: iPhone и Android

| | iPhone (Safari, «На экран Домой») | Android (Chrome, установка) |
|---|---|---|
| Назад | своего жеста нет → наш свайп от края + кнопка ‹ | системный жест/кнопка → `history.back` (шторки в хэше уже это поддерживают) |
| Установка | нет `beforeinstallprompt` → подсказка «Поделиться → На экран Домой» один раз в «Моём баре» | своя кнопка «Установить» через `beforeinstallprompt` |
| Запуск | `apple-touch-startup-image` (чёрный сплэш с логотипом) — иначе белая вспышка | сплэш из манифеста (иконка + `background_color` #000) |
| Иконка | apple-touch-icon 180 | maskable 512 (проверить безопасную зону) |
| Резина при скролле | `overscroll-behavior: none` на корне, чтобы навбар и таб-бар не «отрывались» | так же; отключить pull-to-refresh |
| Статус-бар | `black-translucent` + safe-area (уже) | `theme-color` #000 (уже) |
| Клавиатура | поле не прячется под клавиатурой в редакторе (`visualViewport`) | так же |

## Состояния

- Нет View Transitions — мгновенная смена страниц (как сейчас), шторки и тосты анимируются всё равно (CSS).
- reduced-motion — только fade.
- Медленное устройство — переходы не блокируют ввод; повторный тап во время перехода игнорируется.
- Офлайн — без изменений (всё локально).

## Решения

1. Свайп назад на iPhone — «честный»: под страницей рисуется настоящая предыдущая (роуты той же страницы с её location и скроллом).
2. Платформа — автоматически; на витрине — переключатель iOS / Android / Авто.
3. Установка: тестовый стенд (GitHub Pages) — сразу приложение; Vercel (`VITE_INSTALL_PAGE=1`) — по ссылке в браузере сначала страница установки, «Открыть в браузере» — без установки.
4. Записи пользователей не пересекаются: всё хранится в `localStorage` его телефона (в установленном PWA на iPhone — отдельно от Safari, поэтому ставить лучше сразу).

## Вне рамок

Анимации на основе физики с библиотеками (Framer Motion и т. п.) — только CSS + View Transitions;
жесты «назад» внутри шторок; анимированные иллюстрации бокалов; push-уведомления.
