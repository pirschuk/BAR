# BAR — каталог коктейлей (PWA)

Мобильное PWA-приложение: каталог коктейлей с рецептами, поиском и фильтрами.
Пет-проект, цель которого — взрослый продуктовый и дизайн-процесс внутри
Claude Code: план → дизайн-система → экран → визуальная проверка.

## Стек

- Vite + React + TypeScript (strict) + Tailwind CSS + Lucide Icons + `vite-plugin-pwa`.
- Mobile-First. Базовый вьюпорт **390×844** (iPhone 14/15). Эстетика нативного
  iOS/Android: крупные заголовки, мягкие скругления, нижние шторки, тактильный
  отклик на нажатие.
- Данные — статический `src/data/cocktails.json` (схема — скилл `cocktail-data`).
  Backend нет.

## Команды

- Онбординг отдельно, для просмотра: `/onboarding` (не меняет данные, «Посмотреть ещё раз»).
- `npm run dev` — dev-сервер, http://127.0.0.1:5173 (порт фиксированный, `--strictPort`).
- `npm run build` — `tsc` + сборка в `dist/` от корня `/` (локально, Vercel).
- `npm run build:gh-pages` — сборка с `BASE_PATH=/BAR/` + `dist/404.html` для прямых ссылок.
- `node scripts/serve-gh-pages.mjs` — локальная эмуляция GitHub Pages на http://127.0.0.1:4174/BAR/.
- `npx tsc --noEmit` — проверка типов (её же запускает хук после каждой правки `.ts/.tsx`).
- `npm test` — unit-тесты (vitest, `src/**/*.test.ts`): порции, склонения, фильтр.
- `node scripts/screenshot.mjs <роут> [имя] [--full] [--click <локатор>]` —
  скриншот 390×844 @2x в `.screenshots/`; `--click` повторяемый (Playwright-локатор).
- `node scripts/check-recipes.mjs` — страница рецепта на всех коктейлях: параметры в одну строку,
  без горизонтального скролла, название ≤ 2 строк, контраст текста на тинте ≥ 4.5.
- `python3 scripts/split-shot.py <png>` — нарезать длинный скриншот на экраны по 844.
- `node scripts/validate-cocktails.mjs` — валидация `cocktails.json`.
- `node scripts/make-icons.mjs` — иконки PWA из `public/favicon.svg`.
- `node scripts/make-og.mjs` — картинка превью ссылки `public/og.png` 1200×630 (нужен dev-сервер).
- `node scripts/make-splash.mjs` — заставки запуска iPhone (`public/splash/`), печатает `<link>` для `index.html`.

## Хостинг и поток релиза

- **Две площадки:** на GitHub Pages проверяем фичи и идеи, на Vercel — только готовый функционал.
  1. Работа идёт в ветках `claude/**` → каждый пуш публикует **тестовый стенд** https://pirschuk.github.io/BAR/
     (`.github/workflows/deploy-gh-pages.yml`; полный доступ в браузере, витрина `/design-system`, `/install`, `/onboarding`).
  2. Когда владелец принял фичу — она уходит в `main` → **Vercel** публикует продакшен. В `main` и на Vercel
     руками/автоматически ничего непроверенного не попадает; превью-деплои веток `claude/**` на Vercel выключены (`vercel.json` → `git`).
- **Vercel — продакшен:** от корня `/`, `vercel.json` (rewrites → `index.html`). Сборка `VITE_INSTALL_PAGE=1 VITE_INTERNAL=0`:
  в браузере — **только страница установки** (без обхода), всё приложение — после установки, при запуске с экрана «Домой»;
  служебных страниц нет. Данные (бар, избранное, авторские) — в `localStorage` телефона, между пользователями не
  пересекаются. Node ≥ 22.12 (`engines`); превью ссылки — `og:image` с адресом из `VERCEL_PROJECT_PRODUCTION_URL`;
  кэш: `/assets/*` — навсегда, `sw.js`/манифест/`index.html` — без кэша.
- Базовый путь — только через `import.meta.env.BASE_URL` (роутер — `basename`, манифест —
  `start_url`/`scope`, иконки — относительные пути). Абсолютные `/…` ссылки на ресурсы
  в коде не писать: на Pages они уйдут мимо `/BAR/`. Ссылки роутера (`<Link to="/">`) — можно.

## Процесс (обязателен)

1. `/idea <фича>` — только продуктовое мышление, код не пишем. Результат — `plan.md`.
2. `/code` — реализовать утверждённый `plan.md`: **сначала** компоненты
   в каталоге `/design-system`, **потом** экран.
3. `/look <роут>` — скриншот, разбор глазами, исправление огрехов.
4. `/ref <ссылка|описание>` — новый референс из Mobbin → правила в скилл `design-system`.

Субагенты: `ui-inspector` (визуальная критика по скриншотам), `bartender`
(наполнение и валидация `cocktails.json`, чтобы не засорять основной контекст).

## Правила

- **`/design-system` — источник истины.** Любой UI-элемент экрана сначала
  появляется в каталоге `/design-system` со всеми состояниями (default,
  pressed, disabled, empty, loading), и только потом используется в экране.
  Новые компоненты в обход каталога не заводить.
- **Только токены.** Цвета, радиусы, отступы, тени, шрифты — из токенов
  (`tailwind.config` / CSS-переменные), описанных в скилле `design-system`.
  Никаких «магических» `#hex` и `px` в компонентах.
- **Тач-зоны ≥ 44×44 px**, safe-area через `env(safe-area-inset-*)`.
- **Визуальная проверка обязательна.** После вёрстки любого компонента или
  экрана: dev-сервер → `node scripts/screenshot.mjs <роут>` → открыть `.png`
  через `Read` → проверить (съехавшие блоки, мелкие кнопки, контраст,
  обрезанный текст, safe-area) → исправить → повторить. Показывать результат
  пользователю только после чистого скриншота.
- **Типы не ломаем.** Хук `PostToolUse` гоняет `tsc --noEmit`; при ошибке —
  чинить сразу, не копить.
- Референсы: `refs/` (скриншоты из Mobbin, файлы пользователя). Mobbin
  доступен через MCP (`mcp__Mobbin__search_screens` / `search_flows`),
  сайт mobbin.com из контейнера закрыт прокси — картинки берутся из
  результатов MCP.
- Интерфейс — на русском. Объёмы в рецептах — в мл.
- **Скриншоты: черновые и финальные.** Черновые (самопроверка) — в
  `.screenshots/`, в git не коммитим. Финальные чистовые скриншоты каждого
  этапа (после проверки и правок) копируем в `docs/previews/` с понятным
  именем `<этап>-<экран>[-<состояние|тема>].png` (например,
  `step2-design-system-dark.png`), коммитим в ветку и обновляем
  `docs/previews/README.md` (что на скриншоте, дата, этап). Пользователь
  смотрит их на GitHub — чат картинки из контейнера может не показать.
- Тема одна — тёмная (барная эстетика, акцент `#FF8A3D`), фон — чистый чёрный `#000`,
  все градиенты (обложки, карточки, тинт рецепта) уходят в чёрный. Светлую убрали
  (решение владельца, Итерация 3) — не возвращать без запроса.
- Шрифты — только локальные (без CDN, работают офлайн): заголовки рецепта —
  Unbounded (`src/assets/fonts/`, OFL, `font-display`), остальное — системный стек.
